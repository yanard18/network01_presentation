İmzalama Veri Yapısı & Anahtar Yaşam Döngüsü

SMB paketlerinin dijital imzalama süreci, doğrulanmış kullanıcının parolasından türetilen Session Key ve paket üstverilerinin (metadata) birleştirilerek hash'lenmesiyle çalışır.
1. SESSION KEY (K_session)

Kullanıcının doğrulanmış parolasından/hash'inden türetilen 128-bit gizli oturum anahtarı.

2. MESSAGE BLOCK

Gönderilen paketteki tüm SMB başlık ve veri yükü (payload). Değiştirilmeye karşı checksum gibi hash'lenir.

3. IDENTITIES (IDs)

Orijinal gönderici (sender) ve hedeflenen alıcı (recipient) kimlik bilgileri hash içerisine gömülür.

SMB Signing Aktivasyon Adımları
1. NEGOTIATE SMB Diyalekti & Güvenlik Modu Müzakeresi (İmzasız)
2. CHALLENGE Sunucudan NTLMSSP Challenge Yanıtı Alınır (İmzasız)
3. AUTH REQ NTLMSSP_AUTH İsteği Gönderilir (İmzasız)
4. SESSION KEY STATUS_SUCCESS yanıtında 128-bit Session Key türetilir!
5. ACTIVE SIGN Adım 4 sonrası TÜM PAKETLER SESSION KEY İLE İMZALANIR
Hatalı Parola (Auth Failure)

İstemci NTLMSSP_AUTH aşamasında yanlış parola veya hatalı NT Hash sunarsa:

  • Sunucu LOGON_FAILURE hatası döndürür.
  • Sunucu istemciye Session.SessionKey (K_session) vermez!
  • Oturum Anahtarı Yoksa = İmzalama İmkansızdır! Hiçbir imzalama işlemi başlatılamaz.
STATUS_LOGON_FAILURE -> No K_session -> Signing Aborted
